# 나중에 수정할 때

이 배포본은 코드를 수정하고 GitHub에 저장하면 그대로 반영되는 구조입니다. 별도 설치나 빌드는 필요 없습니다. GitHub에서 파일을 열고 연필 모양의 편집 버튼을 누른 뒤 **Commit changes**로 저장하세요. Pages 배포 작업이 끝나면 사이트에서 확인할 수 있습니다.

## 어디를 고치면 되나요?

| --- | --- |

## 문구만 바꾸는 예

`index.html`에서 다음 문장을 검색합니다.

```html
사장님은 문장을 기다리고,<br>직원은 바나나를 기다립니다.
```

내용을 원하는 문장으로 바꾸면 됩니다. `<br>`은 줄바꿈입니다. 버튼의 `id`, 클래스명, `data-*` 속성은 동작과 연결되어 있으므로 문구만 바꿀 때 함께 지우지 마세요.

`app.js`나 `commissions.js`의 문구를 수정할 때는 문자열의 따옴표와 쉼표를 유지하세요. 직접 입력한 긴 글을 써보고 싶은 것이라면 코드 수정 없이 웹의 외주함에서 **직접 받은 긴 원고 가져오기**를 이용할 수 있습니다.

## README는 자유롭게 바꿔도 되나요?

네. `README.md`는 GitHub 저장소 소개이며, 웹 화면이나 기능에 연결되지 않습니다. 작품 설명, 밈, 제작 노트 등 원하는 내용으로 바꾸셔도 됩니다. 배포 안내는 `docs/DEPLOY.md`에 따로 두었습니다.

## 폴더별 역할

- 루트의 HTML·JS·CSS: 실제 웹사이트. `index.html`이 시작점입니다.
- `fonts/`: 웹과 내려받는 책에서 사용하는 Sunflower 폰트와 라이선스.
- `docs/`: 배포·수정 안내. 게임 실행에는 관여하지 않습니다.
- `tests/`: 무작위 추출·저장 복원·외주·편집부·피로·제본·소리 검증.
- `package.json`: 선택적인 개발 검증 설정. 배포에는 설치 과정이 필요 없습니다.
- `.nojekyll`: GitHub Pages에 정적 파일을 그대로 올리도록 하는 표시.

## 코드 검증 — 선택 사항

Node.js 22 이상이 이미 설치되어 있다면 루트에서 `npm test`를 실행합니다. 외부 패키지를 설치할 필요는 없습니다. 이 배포본에는 27개 검증이 포함되어 있습니다.

CSS나 단순 문구를 바꿨다면 해당 화면을 확인하면 됩니다. 타이핑 규칙이나 저장 방식을 바꿨다면 자동 검증과 실제 원고 완성·제본 흐름을 함께 확인하는 편이 좋습니다.

## 기록을 유지하려면

코드 안의 `localStorage` 저장 키를 바꾸면 기존 기록이 없는 것처럼 보일 수 있습니다. 저장 기능을 바꾸려는 목적이 아니라면 키를 유지하세요. 원고나 책의 기록은 GitHub 저장소에 들어가는 것이 아니라 방문자 각자의 브라우저에 남습니다.
